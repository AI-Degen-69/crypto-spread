# CONSTRAINTS.md — Issue #193: Stats Summary hero cards reflect live data

Binding while `fix/summary-hero-live-data-193` is live. Supersedes the #191
contents. These are gates, not suggestions: a violation blocks the PR.

## 1. Zero regressions

- `python -m pytest -q` must end with **0 failures**, before and after.
  Baseline at planning time: ~390 tests.
- Targeted gate, run first and on every task:
  `python -m pytest -q tests/test_osc_dash_integration.py tests/test_orders_trades_table.py`
- Every new behavior ships with a test in the same commit as the behavior.

## 2. Anti-cheat

- No `@pytest.mark.skip`, no `xfail`, no deleted or weakened assertions, no
  `# noqa` / linter suppressions added to make a gate pass.
- Do not edit an existing test to accommodate new output unless the test
  asserted one of the removed literals; if you do, say so explicitly in the
  commit body.
- Do not assert on live values read from `run/oscillation_summary.json`. That
  file is gitignored and regenerated by the collector, so any test pinned to
  `3,598` or `74.2%` is green on this machine and red on a clean checkout.
  Tests feed their own fixture data into the pure functions.

## 3. Scope fence — one concern per branch

- `server/osc_dash.py` and `tests/` are the only files this branch may touch,
  plus the four per-issue working files (`SPEC.md`, `CONSTRAINTS.md`,
  `tasks/plan.md`, `tasks/todo.md`).
- Do **not** fix the same stale figures in `README.md` or `docs/operations.md` —
  explicitly out of scope per the issue; they get their own change.
- Do **not** touch the four charts in `renderSummaryCharts()`, the other four
  tabs, or `scripts/rebuild_windows.py`.
- Never commit anything under `run/` — it is gitignored capture output.

## 4. No new dependencies

- No new Python package, no new npm package, no new CDN script tag. Chart.js
  4.4.0 is already loaded and is not needed for this change anyway.
- No new API endpoint. `/api/oscillation` already carries the whole payload.

## 5. Correctness gates specific to this change

- **No `NaN`, no `Infinity`, no misleading `0%`.** Every percentage slot with an
  empty or zero denominator renders the literal `—`. This is the defect class
  the issue exists to prevent; it gets a dedicated test.
- **One fetch.** `renderOscillationHero` must consume the payload
  `renderSummaryCharts()` already fetched. A second `fetch('/api/oscillation')`
  is a rejected implementation.
- **Static markup ships placeholders.** Before the first fetch resolves, every
  live slot reads `—`, never a stale numeral and never an empty box.
- **Pure functions stay pure.** `computeOscillationHeadline`, `formatOscPct` and
  `formatOscAsOf` touch no DOM and issue no network call, so the Node harness
  can call them directly.
- **Defensive DOM.** Every element lookup in `renderOscillationHero` is guarded;
  a missing id must not throw and must not abort the rest of the render.

## 6. Performance

- No measurable change to Stats Summary tab-switch latency: the work is summing
  ≤ 20 objects on a payload already in memory. No extra network round trip, no
  extra file read on the server.

## 7. Git discipline

- Branch `fix/summary-hero-live-data-193` off `master`. Never commit to `master`.
- One logical change per commit, conventional commits with a scope, e.g.
  `fix(dash): compute Stats Summary hero figures from /api/oscillation (#193)`.
- Full `python -m pytest -q` green before the PR is opened.
