# ECC Flow Guide — `crypto-spread`

מדריך מקיף לניהול תהליך הפיתוח, הבדיקות, ביקורת הקוד והשילוח באמצעות מעטפת **`ecc-flow`** המבוססת 100% על מנוע ה-**`orch-pipeline`** וסוכני הליבה המקוריים של **ECC (Everything Claude Code)**.

---

## 1. ארכיטקטורת ה-Flow הטהורה של ECC (`orch-pipeline`)

ב-ECC קיים מנוע פייפליין רשמי אחד לניהול פיתוח מקצה-לקצה: **`orch-pipeline`**.
הסקיל **`ecc-flow`** הוא מעטפת אינטראקטיבית מדויקת סביב ה-Pipeline הזה, שמוודאת שהסוכן:
1. **עוצר אחרי כל שלב בודד** ומציג סיכום מובנה בעברית.
2. **מפריד לחלוטין בין שלב השאלות (2א) לשלב התוכנית (2ב)** — חל איסור לכתוב תוכנית לפני מענה לשאלות.
3. **אוכף את שני שערי הברזל של ECC**:
   - **🛑 GATE 1**: אישור תוכנית העבודה על ידך לפני כתיבת שורת קוד אחת.
   - **🛑 GATE 2**: אישור ה-diff והקומיט על ידך לפני push ופתיחת PR.

## 2. חוזה האינטראקציה והעצירה (The Gating Contract)

בסיום **כל שלב בודד**, הסוכן עוצר לחלוטין את הריצה ומציג סיכום מובנה בפורמט קבוע בעברית:

```markdown
---
### 📋 סיכום שלב [מספר ושם השלב]
* **מה הורץ:** [הסוכנים, הפקודות והכלים של ECC שהופעלו]
* **מה בוצע:** [תמצית הממצאים, הקוד, השאלות או ההחלטות]
* **השלב הבא ב-Workflow:** [שם השלב הבא לפי orch-pipeline והסבר קצר]
* **הפקודה להרצה:** `/[command]` (פקודת ECC ייעודית)

💬 **מה ברצונך לעשות?**
השב **"המשך"** כדי שאריץ את השלב הבא בעצמי, או הקלד פקודה / תשובה / שינוי שתרצה.
---
```

הסוכן **ממתין לתשובתך בצ'אט** ולא מתקדם לשלב הבא ללא אישורך.

## 3. מיפוי השלבים והסוכנים המקוריים של ECC

| שלב | שם השלב | סוכנים ופקודות ECC פעילים | מה מתבצע בפועל |
| :--- | :--- | :--- | :--- |
| **0** | **קליטה וחקירה** | `code-explorer` | קריאת פרטי המשימה/Issue, סריקת עץ הקבצים ומיפוי נתיבי ריצה וקונבנציות. |
| **1** | **מחקר ושימוש חוזר** | Context7 / Docs | בדיקת ספריות קיימות, קוד קיים בפרויקט (Pattern Grounding) ומניעת המצאת הגלגל. |
| **2א** | **תשאול ובירור** | — | **שאלות בלבד**: 2–4 שאלות ממוקדות על Tradeoffs וספים. **אין כתיבת תוכנית**. |
| **2ב** | **נעילת תוכנית** | `planner` / `architect`, `plan-canvas` | גיבוש `task_list` ותוכנית יישום מפורטת. **🛑 GATE 1**: עצירה לאישור המשתמש. |
| **3** | **מימוש ב-TDD** | `tdd-guide`, `/build-fix` | כתיבת בדיקות תחילה (Red), מימוש הקוד (Green), ריפקטורינג נקי, תיקון כשלים. |
| **4** | **ביקורת רב-סוכנית** | `code-reviewer`, `python-reviewer`, `security-reviewer` | ביקורת עמידה בדרישות, בדיקת איכות Python (PEP 8, asyncio, טיפוסים) ואבטחה. |
| **5** | **שילוח ו-PR** | `/pr` (או `/prp-commit`) | **🛑 GATE 2**: אישור קומיט. יצירת Conventional Commit ופתיחת PR מקושר ב-GitHub. |
| **6** | **בקרת איכות סופית** | `pr-babysitter` / CI Gate | מעקב אחרי בדיקות ה-CI וביקורת CodeRabbit האוטומטית עד מצב ירוק למיזוג. |

## 4. מנגנוני הבטיחות הפעילים (ECC Hooks ב-Antigravity)

במהלך כל שלבי ה-Flow, פועלים מנגנוני ה-Hooks של ECC ברקע דרך `.agents/hooks.json` ו-`.agents/hooks/antigravity-hook-runner.js`:

1. **`block-no-verify`**: חוסם ניסיונות לעקוף בדיקות ב-git (`git commit --no-verify`, `git push --no-verify`).
2. **`config-protection`**: מונע פגיעה או שינוי של קובצי קונפיגורציית בדיקות ולינטרים (`ruff.toml`, `eslint.config.js`).
3. **`governance-guard`**: עוצר פעולות הרסניות (`rm -rf`, `git push --force`) ודורש אישור מפורש מהמשתמש.

## 5. מקרא פקודות שימושיות

```text
# הרצת ה-Flow האינטראקטיבי השלם:
/ecc-flow <תיאור המשימה או מספר Issue>

# הפעלת פקודות ה-Pipeline הישירות של ECC:
/orch-add-feature <משימה>     # הפעלת ה-Pipeline להוספת פיצ'ר חדש
/orch-fix-defect <באג>        # הפעלת ה-Pipeline לתיקון באג
/orch-change-feature <שינוי>  # הפעלת ה-Pipeline לעדכון התנהגות קיימת
/orch-refine-code <קוד>       # הפעלת ה-Pipeline לריפקטורינג
/feature-dev                 # הגרסה הקלאסית המונחית של ECC
/plan                        # כתיבת תוכנית עבודה
/build-fix                   # תיקון תקלות קומפילציה ובנייה
/code-review                 # ביקורת קוד רב-סוכנית
/python-review               # ביקורת מומחה Python
/pr                          # קומיט ופתיחת Pull Request
```
