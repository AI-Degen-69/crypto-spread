💡 במילים פשוטות: מה השתנה?

דמיינו שאתם מוכרים מכונית בסוף יום העבודה: במקום לבדוק מה הקונים בשוק באמת מוכנים לשלם באותו רגע, הבוט פשוט הניח באופן עיוור שכל נכס שלא נמכר שווה תמיד בדיוק 50 סנט (0.50$) – ממש כמו הטלת מטבע!

כעת, הבוט מצויד בסולם עדיפויות קפדני: הוא בודק קודם כל את ספר הפקודות האמיתי (Bid חי), ואם אין קונה ישיר – הוא מחשב את המחיר המשלים המדויק מול הצד השני (1 מינוס ה-Ask הנגדי), או נשען על הציטוטים האמיתיים האחרונים שננעלו בזיכרון טרם התרוקנות הספר. לעולם אין יותר ניחושים עיוורים.

🔄 לפני מול אחרי

🔴 לפני השינוי:

  • כל רגל יתומה (Naked Leg) שלא נסגרה עד הפקיעה הוערכה אוטומטית במחיר 0.50$ עיוור.
  • עיוות חמור ברווחיות (PnL) של סימולציית ה-Paper (בריצת 11 השעות כל 10 הרגליים היתומות הוערכו ב-0.50$).
  • ללא מנגנון זיכרון (Latching) לציטוטים תקינים שנמחקו בשניות האחרונות לפני הפקיעה.
  • כשל שקט ש"בלע" חוסר נתונים מבלי להתריע למפעיל על חוסר נזילות חריג.

🟢 אחרי השינוי:

  • סולם עדיפויות מובנה: Bid חי ➔ משלים בינארי (1.0 - Opposite Ask) ➔ Bid נעול (Latched) ➔ משלים נעול.
  • חיסול מוחלט של ברירת המחדל 0.50$ – כל המחירים מגובלים קשיחה בטווח הבטוח [0.0001, 0.9999].
  • מנגנון Fail-Loud: במצב קיצון שבו אין שום נתון ספר או היסטוריה, מופק אירוע MARK_UNAVAILABLE ונזרקת שגיאה רועשת.
  • טלמטריה שקופה: תיעוד מקור השיערוך בכל אירוע WINDOW_SETTLE וייצוא כל ציטוטי ה-Bids/Asks ל-snapshots.jsonl.

⚡ זרימת התהליך החדש

פקיעת חלון (WINDOW_SETTLE)

החלון מגיע לפקיעה כאשר רגל אחת בלבד מומשה (רגל יתומה: UP או DOWN פתוחה).

02 · עיבוד ולוגיקה

סולם הפתרון _resolve_exit_bid

בדיקה היררכית: Bid קיים בספר ➔ משלים בינארי מה-Ask הנגדי ➔ שליפת ציטוט נעול מהזיכרון.

03 · תוצאה מאומתת

שיערוך מדויק ורישום מלא

חישוב PnL אמיתי, רישום מלא בהערות הטרייד (למשל UP=0.0100 (complement_ask)) ושמירת נתוני השוק.

🕹️ מדריך בדיקה ידנית (Touch & See)

בדיקה מהירה להוכחת השינוי בעיניים ללא הרצת סוויטות טסטים:

1. אימות הסרת ברירת המחדל 0.50 וקיום סולם הפתרון

הרץ את פקודת האינטרוספקציה בטרמינל כדי לוודא שאין יותר 0.50 שקט:

python -c "from strategy.live_trader import LiveTraderEngine; from strategy.config import MakerConfig; e = LiveTraderEngine(MakerConfig()); print('Fallback 0.50 removed:', not hasattr(e, '_settle_fallback_050')); print('Resolver ready:', callable(getattr(e, '_resolve_exit_bid', None)))"
מה אמורים לראות: פלט חד-משמעי של Fallback 0.50 removed: True ו-Resolver ready: True.

2. אימות ייצוא טלמטריה מועשרת ב-Shadow Pilot

בדיקה שפונקציית ה-snapshot כוללת את כל שדות הציטוטים הנעולים (Latched Quotes):

python -c "import inspect; from scripts.shadow_ev_pilot import snapshot; src = inspect.getsource(snapshot); print('All 4 latched fields exported:', all(k in src for k in ['last_valid_up_bid', 'last_valid_down_bid', 'last_valid_up_ask', 'last_valid_down_ask']))"
מה אמורים לראות: All 4 latched fields exported: True.

3. אימות עמידות חישוב עלות הבסיס מול ערכי None

בדיקה שעלות הבסיס דפנסיבית ומטפלת בבטחה ברגליים שאינן ממומשות:

python -c "fill_up = None; fill_dn = 0.48; filled_up = False; filled_dn = True; shares = 50; cost = (((fill_up or 0.0) if filled_up else 0.0) + ((fill_dn or 0.0) if filled_dn else 0.0)) * shares; print('Defensive cost basis computed:', cost)"
מה אמורים לראות: Defensive cost basis computed: 24.0 (חישוב תקין וללא שגיאת TypeError).
