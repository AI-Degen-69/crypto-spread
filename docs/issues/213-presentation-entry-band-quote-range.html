💡 במילים פשוטות: מה הבעיה ואיך פתרנו אותה?

בעבר, למערכת היה "שומר סף" קשוח וקצר-ראייה: הוא הסכים לצטט רק אם המחיר של השוק היה צמוד בדיוק ל-50 אגורות (0.45 עד 0.55). ברגע שהשוק חווה תנודה קטנה והמחיר זז ל-56 אגורות, שומר הסף נכנס לפאניקה, נעל את הדלת (band_skip = True), זרק את המפתח, והשבית את הבוט מציטוט לכל אורך 300 השניות של החלון – גם אם שתי שניות לאחר מכן המחיר חזר בדיוק למרכז!

במודל החדש (כלל 6 ו-ADR-0003):

  • שחרור הנעילה לצמיתות: אין יותר השבתה גורפת! אם המחיר יוצא מהטווח, הבוט ממתין לאותו טיק בודד בלבד (Tick hold), וברגע שהמחיר שוב בפנים – ממשיכים לצטט מיד.
  • טווח מסחרי רחב: במקום 0.45–0.55 הצר, הבוט רשאי לצטט בכל מקום בין 0.10 ל-0.90 (80% מטווח החוזה).
  • ציטוט עוקב-מיד: ההזמנות אינן עגונות ל-0.50 אלא למיד האמיתי של השוק ברגע זה: mid - offset.

🎮 סימולטור אינטראקטיבי: התנהגות הציטוט והשוואת מודלים

הזיזו את הסליידר של מחיר האמצע (Market Mid) כדי לראות כיצד המודל החדש מתנהג לעומת מנגנון ה-Entry Band הישן שנמחק:

🔄 לפני מול אחרי

🔴 לפני השינוי (Legacy Entry Band):

  • עגינה קשיחה ל-0.50: טווח כניסה צר של 0.45 עד 0.55 בלבד.
  • נעילה הרסנית (Latching): חריגה בטיק בודד הפעילה band_skip = True שנשאר נעול לצמיתות עד תום 300 השניות של החלון.
  • הזמנות סטטיות: ציטוט במחיר קבוע מול 0.50 במקום לעקוב אחרי מרכז השוק האמיתי.
  • היעדר שוויון: חוסר עקביות במימוש ובשמות הפרמטרים בין הלייב טריידר לבקטסט.

🟢 אחרי השינוי (Rule 6 / ADR-0003):

  • טווח מסחרי רחב [0.10, 0.90]: פעילות מלאה על פני 80% ממנעד ההסתברויות של הפולימרקט.
  • בדיקה לטיק בודד ללא נעילה: אם המיד חורג, הבוט ממתין באותו טיק בלבד. ברגע שהמיד חוזר – חוזרים לצטט מיד!
  • ציטוט עוקב-מיד (Dynamic Mid-Anchored): פקודות מחושבות כ-mid - offset ומשלימתן (1 - mid) - offset.
  • שוויון התנהגותי מוחלט 1:1: קוד לוגיקה תואם לחלוטין בין מנוע הבקטסט ללייב טריידר, מגובה בחבילת טסטים מלאה.

⚡ זרימת התהליך והארכיטקטורה

01 · קריאת מיד מספרי האורדרבוק

קריאת Mid מדויקת

המנוע מוודא קיום ספר דו-צדדי (Best Bid ו-Best Ask תקפים) ומחשב את המיד הרציף: mid = (best_bid + best_ask) / 2.

02 · הערכת Quote Range פר-טיק

אימות טווח ללא נעילה

הערכת תנאי quote_lo <= mid <= quote_hi פר-טיק. אם מחוץ לטווח, מדלגים על טיק זה בלבד ללא שינוי דגלים וללא נעילת המנוע.

03 · פריסת פקודות עוקבות-מיד

ציטוט דינמי סימטרי

חישוב מחיר ביד YES כ-mid - offset ומחיר ביד NO (משלים) כ-(1 - mid) - offset, עם וידוא עלות זוג נמוכה מ-1.00$.

🕹️ מדריך בדיקה ידנית (Touch & See)

בדיקה פשוטה להוכחת השינוי בעיניים בדשבורד האמיתי וב-CLI ללא הרצת טסטים:

1. בדיקת פרמטרי ה-Quote Range בממשק הדשבורד

python -m uvicorn server.osc_dash:app --host 127.0.0.1 --port 8802
מה אמורים לראות: פתחו דפדפן ב-http://127.0.0.1:8802, היכנסו לכרטיסיית Backtest. ודאו כי קיימים השדות Quote Range Lo (ברירת מחדל 0.10) ו-Quote Range Hi (ברירת מחדל 0.90). אין יותר שום אזכור לשדה הישן entry_band.

2. בדיקת נקודת הקצה ב-REST API

קריאה ל-API כדי לוודא תמיכה מלאה בפרמטרים החדשים:

curl "http://127.0.0.1:8802/api/backtest?quote_lo=0.10"e_hi=0.90&offset=0.02"
מה אמורים לראות: תגובת JSON תקינה שבה מוחזרת תוצאת הבקטסט תוך כיבוד הגבולות 0.10 עד 0.90.

3. בדיקת הרצה ישירה ב-CLI

הרצת מנוע הבקטסט באמצעות ה-CLI עם הדגלים הרשמיים:

python -m scripts.backtest run/ticks --quote-lo 0.10 --quote-hi 0.90 --offset 0.02
מה אמורים לראות: פלט טבלאי של חלונות מסחר שבוצעו, שבו עסקאות מבוצעות בכל רחבי הטווח 0.10–0.90 ולא נחסמות כאשר המיד סוטה מ-0.50.
