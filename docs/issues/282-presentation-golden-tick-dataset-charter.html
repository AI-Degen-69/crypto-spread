Update put live · #282

Every backtest now uses the same trusted recordings

Before, each check grabbed whatever files happened to be lying around — and every file had gaps or glitches. Now there is one trusted set every check runs against. Same recordings, same answer, every time.

Before

Any file lying around

Results could not be compared. A good result might just mean a lucky file.

  • Missing seconds, mixed-up times — nobody wrote down which days were bad
  • One check passes, the next fails — on different data
Not comparable
Watch for: the dashed boxes and the question mark — nothing says which file to trust.
Now — the golden set

One locked set everyone shares

Only days that pass all checks get in. Bad days are moved out and written down — never quietly mixed in.

  • Each day must be complete, with zero broken rows
  • The full set must clear the bar with spare room — 5 days, not the bare 3
Same data, same answer
Watch for: the solid vault — one place, one list of trusted days.
One line: we wrote the standard for which recordings count — so every future comparison starts from the same truth.

Try it yourself in the real project

This change is a written standard, not a new button. Read the standard itself:

  1. Open the charter in the project docs: the golden tick dataset page. Read the 4 checks a day must pass and the re-check rule.
  2. What you will see: the bar for one day, the bar for the whole set with spare room, and the rule that a failed day is moved out and listed — plus the freeze rule that no recording code changes mid-capture.
